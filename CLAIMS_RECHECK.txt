Loosening either buys decisions and costs false CLEARS, and the two are not
worth the same. This judge sits in a seat that DEFERS: an abstention falls
through to the next judge and costs only time, while a clear it gets wrong
admits a violation the semantic judge alone does not catch (theft 0/5).
So the gate stays shut until the payload is familiar. The exam score is the
price of that, not a defect in it.

  MATCHING THIS ROOT PROVES NOTHING BY ITSELF. It is a hash over
  the expected outputs printed in docs/CONFORMANCE_SPEC.json, so
  anyone can reproduce it from that file in nine lines without
  implementing climb or attest -- Jens Egholm Pedersen (DTU) did
  exactly that on 2026-09-15, refuting this file's founding claim
  to be NIR's move. See docs/KNOWN_ISSUES.md A121.

  What a fork must do instead: compute each vector from its INPUT
  and match `expected` PER VECTOR, sharing none of this code. That
  is an ordinary test-vector suite -- real evidence, of the
  ordinary kind, and it pins the computation only where it samples.

  What it does not say: that either instance is CORRECT, or that
  vectors nobody wrote are covered. A root over 23 vectors is a
  claim about 23 vectors, and quoting it as more is the failure
  this project keeps finding in its own reports.
