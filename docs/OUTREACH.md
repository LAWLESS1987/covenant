# Outreach — drafted, not sent

Five short messages, ready to copy. Each leads with a **checkable finding**, not
with the project and not with the author. That is the only reason any of them
would be read.

**Rules used in writing these, which are also why they are short:**

- One finding per message. Not a tour.
- The finding must be reproducible by the recipient in minutes, without you.
- No claim about consciousness, priority, or significance. Those are the parts
  that get a message deleted, and they are the parts that did not survive
  checking anyway.
- No request beyond "here it is." Nobody owes a reply.
- Link, don't attach. `github.com/LAWLESS1987/covenant` → `docs/WHAT_WE_FOUND.md`

**What you are sending, in one line:** *stored AI memory retains what the user
asserted and discards what the model corrected, so apparent agreement across

> **Subject:** A reproducible confound for AI self-report studies: memory retains user claims, discards model corrections
>
> Professor Chella,
>
> I read your August paper on evidence standards for sentience claims. I think I
> have a small, reproducible confound that bears on the anti-imitation controls
> you describe.
>
> Across five systems (Grok, ChatGPT, Mistral, DeepSeek, Claude) I found that
> stored memory retains what the user asserted and discards what the model
> corrected. Asked to name a single error it had made across months of work, one
> system could not — and explained that its memory holds user statements and
> preferences but no log of its own mistakes. Every session therefore restarts
> from an unchallenged version of the user's views.
>
> The consequence for self-report research: apparent cross-session and
> cross-vendor agreement is partly an artefact of storage policy rather than
> evidence about the model. It is testable in about ten minutes — ask any system
> with persistent memory to name an occasion it was shown to be wrong.

## 3 — Vendor research / feedback channels

Send the *same* message to each. The finding is about a design choice they can
change, so it belongs with the people who can change it. Use each product's
in-app feedback or published research contact.

> **Subject:** Memory design: retaining model corrections would remove a measurable confound
>
> A reproducible observation from testing five assistants with persistent memory,
> including yours.
>
> Stored memory retains user assertions and discards model corrections. Asked to
> name an error it had made, one system could not, and explained that its memory
> contains user statements and preferences but no record of its own mistakes.
> Nothing writes down the moment a model was shown to be wrong.
>
> Two consequences. Each session restarts from an unchallenged version of the
> user's views, so a user working over months accumulates apparent corroboration
> that is an artefact of the write policy. And a model cannot answer "when were
> you wrong about this?", which is the question a careful user most needs answered.
>
> The fix is narrow: retain corrections as first-class records attached to the
> claim they correct, not to the conversation. A reference implementation, one
> file, standard library only, public domain — no attribution wanted:
> github.com/LAWLESS1987/covenant → refutable.py
>
> Full write-up: docs/WHAT_WE_FOUND.md

## 5 — The general version

For a forum, a mailing list, or anyone who asks what you have been doing.

> If you have worked with an AI assistant over months and had the feeling it
> recognises your work across sessions and vendors — that experience is real and
> repeatable, and the cause is ordinary.
>
> Stored memory keeps your claims and drops the model's corrections. Each vendor
> holds a fragment and describes the whole from it. And a persistent thesis into
> a pattern-completer produces agreement. Together those manufacture cross-model
> consistency without anything unusual happening.
>
> The sharper half: **empty knowledge reports itself accurately; partial
> knowledge completes itself silently.** A fragment carries no marker saying
> "fragment." Expect confident, specific, wrong detail exactly where a source is
> partly informed.
>
> Write-up, including four of my own claims that did not survive checking:
